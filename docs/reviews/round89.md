## ② 长文本编辑体验专项（注入 12.5k 字符转录条目 longtext.wav，含 800 字符无空格单行）【实测】

### P3-①：Correct 编辑框固定 2 行，万字长文在"钥匙孔"里编辑

- 复现：对 12.5k 字符条目点 Correct → 编辑框仅约 2.5 行高（【源码】History.tsx `rows={2}` 固定），需在框内反复滚动定位要改的词，改几千字的转录几乎不可用。输入无卡顿、保存正常、raw 保留，功能面无损，纯尺寸问题。
- 修法 ~5 行：按内容行数自适应（`rows=min(max(2, 行数), 14)`）或改用 CSS 自动增高；听写短句不受影响。

### P3-②：无空格超长字符串横向溢出卡片

- 复现：条目含 800 字符无空格单行 → 该行不折行，横向溢出卡片边界直到窗口边缘（实拍）。触发面窄（口述 URL/连续英数字/转录外文长串），但一旦出现整页布局被破坏。
- 修法 1 行：正文容器补 `break-words`（overflow-wrap:anywhere）。

- 观察（不立案，建议 v0.15 一并做）：长条目在列表中全文展开无折叠，一条万字转录霸屏、滚过它要十几轮滚轮——建议默认 line-clamp 8-10 行 + 「展开」（~15 行），与搜索/编辑/删除均不冲突。
- 组合行为全过：搜索过滤态（按 personaName 命中）下编辑长条目 → 过滤保持、仍命中、保存即时生效；编辑不触发学词（转录与听写同口径，第 83 轮已验源码路径，本轮行为一致）。
