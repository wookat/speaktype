## 二、P1：双击判定不排除组合键——RightCtrl+C 连按两次会误进免按

**实测复现**（SendInput 脚本，非猜测）：模拟「RightCtrl+C 复制，150ms 后再来一次」（每次 Ctrl 按下约 60ms），悬浮条立即出现，免按连续听写被误启动——用户只是连着复制两次，麦克风就开了。

**根因**：`hotkey.ts` 的双击判定只看 hold 键两次短敲的间隔（≤400ms），两敲之间/按住期间按了其他键（C、V、方向键）不取消 tap 状态（`onKeyDown` 其他分支不重置 `lastTapAt`）。习惯用右 Ctrl 做快捷键的用户（笔记本单手 Ctrl+方向、Ctrl+C/V）日常必踩；误启动是「无感开麦」，观感接近隐私事故。

**修复建议**：hold 键按住期间或两敲间隔内收到任何其他 keydown → 视为组合键，重置 `lastTapAt = 0`（一行状态清理）；回归用例补「RightCtrl+C ×2 不进免按」「纯双敲仍进免按」。

## 三、P2

**P2-a ITN 相邻转换结果无分隔直接拼接**：mock 返回「这次活动花了两千五百分之五十的人迟到了」→ 落字「这次活动花了**250050%**的人迟到了」。「两千五」→2500 与「百分之五十」→50% 各自正确，但相邻拼接后不可读（原文本身有歧义，属对抗样例，故 P2 不是 P1）。建议：两个转换片段相邻时中间补一个空格，或检测到数字字符相邻时放弃后一处转换。

**P2-b 旧 VAD 增强包残留 ~33MB 不清理**：升级用户 `%APPDATA%\SpeakType\vad` 里旧包的 `onnxruntime.dll / DirectML.dll / msvcp140_1/_2.dll / onnxruntime_binding.node`（合计 ~33MB）永久残留。新代码只认 `silero_vad.onnx`，功能不受影响（本机即迁移场景，实测正常），但建议加载路径里顺手 `rmSync` 旧文件名单，或在 migrate.ts 清理。

## 五、幻听 partial「我。」

静音免按下挂机观察 ~40s（Silero 开）：悬浮条无 partial 出现，未复现「我。」。**环境限制说明**：本机验收走 mock 云通道（无流式 partial），partial 幻听只会出现在豆包/本地流式通道——需要在真机豆包环境观察。从机制上讲，Silero `voicedMs=0` 的静音段 finalize 已被 noSpeech 拦截不落字，剩余风险只是**录音中悬浮条上闪现的 partial 字幕**，属观感问题：可在 renderer 侧对「单字+标点」的 partial 做 200ms 去抖再显示，成本低。
