## 3. 专项 b：ko 增强标点行为 + 历史导出/剪贴板边界

### 3.1 ko（韩文）增强标点

mock 注入无标点韩文长句（正常含词间空格）：

| enhancedPunct | 结果 | 判定 |
|---|---|---|
| 关 | `내일 오후 세시 반에 회의가 있으니 … 바랍니다`（空格完整保留，无标点补充） | 可接受【实测确认】 |
| 开 | `내일오후세시반에회의가있으니자료를준비해주시기바랍니다…바랍니다.`（**全部词间空格被吞**，仅补尾句号） | **P2-2221**【实测确认】 |

根因【推测】：punct-ct 仅覆盖中英，对韩文按字符级分词重拼且不还原空格；且空格坍缩后的输出按空白分词只剩 1 词，恰好绕过 `needsPunctuation` 的兜底门槛（<6 词视为无需标点），被当作有效模型产出直接采纳——#313 的回退分支对 ko 失效。韩文以空格分词，该输出不可读，属输出损坏。

### 3.2 历史页导出/剪贴板边界

造边界条目：多行文本（3 行，含 `-`/`#` Markdown 特殊字符）、10,003 字符超长文本。

- 条目 Copy 按钮：多行文本剪贴板逐字节一致（53 字符含换行）【实测确认】。窗口未聚焦时 `navigator.clipboard` 写入静默失败属 Web API 限制，真实用户点击必有焦点，不立案。
- 导出 Markdown：UTF-8 BOM 存在、多行条目续行两空格缩进保持在同一列表项、10k 超长文本完整不截断【实测确认】。
- 搜索过滤后导出：仅导出过滤命中的 1 条【实测确认】；无匹配时导出按钮隐藏【实测确认】。
- 失败条目从导出中排除：源码 `status !== "failed"` 过滤【推测，源码级】，本轮无失败条目未实测。

## 4. 立案汇总

- **P2-2221（新）**：韩文 + 增强标点开启时词间空格全部丢失，输出不可读（输出损坏级）。现象【实测确认】，根因【推测】见 3.1。建议：`applyModelPunctuation` 对含 Hangul（`\uac00-\ud7af`）输入直接跳过模型或校验模型产出的空格保真度（如输出长度/空格数与输入偏差过大则回退原文）。

观察项（不立案）：
- portable exe 删除后 Run 值永久残留，Windows 静默忽略无用户可感知影响（见 2.2）。
- 日文句尾句号被剥除（`keepCjkPeriod=false`）是既有设计，免按模式保留句号（#313 已验证），非缺陷。
