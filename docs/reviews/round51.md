## 1. 悬浮条/toast 位置专项 —— 本机能力内全过，两项环境限制如实标注

- 【源码】定位逻辑：dockPanel/dockToast 均取「鼠标所在显示器的 workArea」计算居中贴底（windows.ts:177-195），天然多屏跟随 + 避让任务栏任意边 + Electron DIP 坐标系天然适配 DPI。
- 【实测】任务栏移到**顶部**（workArea Y=40）：口述期间字幕胶囊仍在屏幕底部居中，不与顶部任务栏冲突、不被遮挡（实拍 taskbar-top.png）。
- 【实测】任务栏移到**左侧**（workArea X=62）：胶囊在剩余工作区内水平居中（整体右移 62px 的一半），贴底正常（实拍 taskbar-left.png）。
- 【实测】任务栏还原底部后位置恢复正常。
- 【未验证-环境限制】DPI 125%/150%：本机虚拟显示器的缩放下拉为禁用状态（ms-settings:display 实查），自定义缩放需注销会话，无法安全执行；多显示器：虚拟环境无法添加第二屏。**代码层判断**：坐标全走 Electron DIP 与 workArea，DPI/多屏适配面风险低；主窗口还有「保存位置落在已拔显示器时回主屏居中」守卫（windows.ts:49）。建议有真实多屏/高 DPI 设备时人工抽一次即可。

## 2. 人设规则边界五项 —— 引擎语义全部正确，UI 侧两处可见性欠账

测试环境：mock 润色端点（127.0.0.1:18099，Test connection 实测 Connected）+ 打包版实测。

| 用例 | 结果 |
|------|------|
| 同一应用两条规则指向不同人设 | 【实测】先命中先用：rule1(notepad.exe→To my boss) + rule2(NOTEPAD→TempZ)，Notepad 口述命中 To my boss（历史 personaName 实证）。列表顺序即优先级，但 UI 无任何「靠前优先」提示（观察项，建议 hint 一句） |
| 规则关键词大小写 | 【实测】不区分：删掉 rule1 后大写「NOTEPAD」正常命中 notepad.exe → TempZ（源码 toLowerCase 双侧） |
| 规则指向已删除人设 | 【实测】删除 TempZ 后规则仍存死 id（speaktype.json 实查 `custom-17868…`），口述静默改道 Default（findPersona 兜底 BUILTIN[0]）；UI select 因无匹配项显示「Default」但存储值未变——显示与存储不一致，用户不知道规则已失效改道。**P3-①** |
| 空规则（match 为空） | 【实测】跳过不匹配（needle 空即 skip），口述走当前人设 To my partner，无崩溃；空行保留在 UI 无校验（可接受） |
| 命中优先级直觉 | 先命中先用符合直觉（IDE 场景常用），源码注释明确 |

**P3-① 修法论证**：删除人设时顺带清理/重指规则最干净——deletePersona 处把 `appPersonas` 中 personaId 命中者的规则同步删除或弹一句「N 条规则已指向默认人设」toast（~8 行）；纯 UI 侧修（select 显示红色「已删除」占位）不解决静默改道本质，推荐前者。

## 3. 自由挑刺：自定义人设删除无确认 —— P3-②

- 【实测】TempZ Persona 卡片点「Delete」即刻永久删除：无确认对话框、无 Undo toast、prompt 内容（用户可能精心调过几百字风格指令）瞬间丢失。对比：清空历史有两步确认、自动学词有 Undo——删除人设是全应用唯一「一键不可逆」的破坏性操作。
- 修法论证：与清空历史对齐的两步确认（点一次变红「确认删除？」再点生效，~10 行），或删除后 6s Undo toast 复用现有 toast 通道（~15 行）。推荐前者，交互成本更低。
