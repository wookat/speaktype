## 2. 专项 A：设置「完全重置」入口设计论证

### 现状盘点（打包版 UI 实查 + 磁盘实查）

| 数据类别 | 磁盘位置 | 现有 UI 重置手段 |
|---|---|---|
| 历史 + 统计 | `%APPDATA%\SpeakType\history.json` | History → Clear all（两步确认，#274 后统计一并清零）✔ |
| 词典 | speaktype.json 内 | Dictionary → Clear（两步确认）✔ |
| 设置项 | `%APPDATA%\SpeakType\speaktype.json` | ✘ 无「恢复默认设置」入口（General/Speech/About 三个 tab 逐屏截图确认，源码 grep 亦无 reset 相关 IPC） |
| 本地模型 | `%APPDATA%\SpeakType\models\`（sensevoice-small 228MB） | ✘ 无删除模型入口，UI 只有 Download/Model ready |
| 日志 | `%APPDATA%\SpeakType\logs\` | ✘ 仅 About → Open log folder（手动删） |
| 渲染缓存 | GPUCache/DawnGraphiteCache 等 | ✘ 无入口（量小，<1MB） |

证据：`ss_85276001.png`（General 底部到 Theme 为止无重置项）、`ss_dbdcefed.png`（About 无重置项）、`ss_d94d136b.png`（Speech 模型区无删除按钮）、磁盘清单命令输出。

### 论证与建议（P3，设计提案，未写码）

1. 用户痛点真实存在：换机/转卖/隐私清理/故障自救（配置损坏目前只能靠 .bad 自动恢复）场景下，用户需手动定位 %APPDATA% 删目录，对普通用户不可达。
2. 模型是最大盲区：228MB 的模型换用后成为孤儿文件，无 UI 可回收，长期使用多模型会累积 GB 级残留——这比「完全重置」更高频，建议模型下拉旁加「删除已下载模型」。
3. 建议形态：Settings → General 底部（或 About）加「重置与数据」分组：
   - 「恢复默认设置」（仅 settings，两步确认）；
   - 「完全重置」（列明将删除的六类数据与体量、输入 RESET 或倒计时确认、执行后重启到 onboarding）；
   - 危险操作用红色次级按钮，遵循现有 Clear all 的两步确认模式。
4. 反面约束：不要把「清历史」「清词典」从原页面挪走（就地管理直觉正确），完全重置只做汇总入口。

## 3. 专项 B：免按 30 分钟长会话内存稳定性

方法：`Alt+Q` 06:54:41 进入，07:24:38 退出（29m57s）；假麦克风每循环 ~8.2s 产生一次 VAD 自动分段；后台脚本每 15s 采样 SpeakType 进程树（125 个样本）。

结果：

| 指标 | 数值 | 判定 |
|---|---|---|
| finalize 次数 | 218（~8.2s/句，全程无中断） | ✔ |
| history 条数 | 224 = 6（soak 前）+ 218，逐句对应零丢失 | ✔ |
| 进程数 | 全程恒定 9 | ✔ |
| WorkingSet | 571 → 603–638MB 平台震荡 | ✔ 稳定 |
| PrivateBytes | 680 → 808MB（+128MB；每 10 分钟增量 67→39→22MB，递减） | ⚠ 缓增趋稳 |
| error/fail 日志 | 0 条 | ✔ |
| soak 后 UI | Settings/History 页正常渲染，224 条历史列表流畅滚动 | ✔ |

判定：30 分钟量级无泄漏危机、无功能退化。私有内存单调缓增但增速递减，更像缓存/堆增长而非线性泄漏；列为 P3 观察项，建议下轮做 60–90 分钟延长 soak 确认是否收敛。证据：`C:\Users\Administrator\r186\mem.csv`、main.log finalize 序列、`ss_da60480b.png`/`ss_37a60296.png`。

已知行为再现：退出免按时产生 1 条 3s 短段历史（History 首条「…再改一。」，`ss_37a60296.png`），与 SKILL 记录的退出竞态一致，未升级为缺陷。
