### 定位分析（逐层排除）

1. **排除模型识别层**：hold 模式（整段离线解码）同样本 0 丢；
2. **排除免按首句路径**：无 carry 的首句 0 丢；
3. **锁定 Silero 起声判定 + carry 边界联合**：丢字只出现在 Silero 开 + 停顿 ≤2.2s 的 carry 句；main.log 显示丢字句 finalize `durationMs` 与 peak 对照几乎相同（如「市场部」句 5246ms vs 5241ms）→ 音频缓冲长度未变短，**是句首帧未被判为 voiced 而被起点裁剪/延迟入 buffer**。与源码中「carry 帧用 peak 阈值更新 lastVoiceAt、voiced 判定却用 sileroMs」的口径不一致方向吻合；3.0s 停顿即可让起声判定赶上，2.2s 内则概率性截头。

### 结论与建议

- **值得修**（丢字率 ~21% 且是句头实义字，直接损害正文）。复现条件明确：Silero 开 + 多句连续免按 + 句间停顿 ≤2.2s + ≥2 循环。

关键观测：① 22+ 次**零错字**，重复完全稳定；② SenseVoice 给独立命令词**一律加句号**；③ 3s 停顿下相邻两个短命令词偶有合并进同一 finalize（「删除上一句。换行。」2/2 合并）；④ 独立短命令（voicedMs 低至 360ms）正常触发 finalize 不被丢弃。存证 `r255_cmd.txt`，截图 ss_59a53793.png。

### 六项论证

1. **候选命令集（建议最小集 4 个）**：
   - 「换行」「另起一段」：与 #354 自动分段互补，用户手动控制段落，价值最高、实现最简（改落字 glue）；
   - 「删除上一句」：免按听写最高频的纠错动作（说错一句重来），可用记录上句落字长度 + 合成 Backspace 实现；
   - 「撤销」：等价 Ctrl+Z 转发，兜底；
   - 暂不入集：「发送」（回车语义随应用差异大、误触代价高——聊天框即发出）；「全部删除」（破坏性大，误触代价不可逆）。
2. **触发语法**：仅当**整条 finalize == 命令词（去尾部标点后）**才触发；嵌入句照常落字。依据：实测嵌入句转写含命令词原文（如「这个方案删除上一句我们再讨论」），全文包含匹配必误伤；而独立命令词输出完全稳定，整句精确匹配误触率实测为 0/8（8 条嵌入样次均未误触发条件）。需处理：去尾部「。」；一个 finalize 含多命令时按「。」切分逐个匹配。
3. **挂点**：finalize 文本确定后、hotword 纠错之后、落字（paste/type）之前——即 dictation.ts 现有 paraBreak 判定同一位置，命中命令则拦截落字改执行动作。复用 #354 已打通的路径，不新增管线。
4. **五语言词表**：随 locale 静态词表（zh/en/ja/ko/…各 4 词，如 en: "new line"/"new paragraph"/"delete last sentence"/"undo"），本轮仅实测 zh；其他语言词表的 ASR 稳定性**未验证**，实现时需逐语言用同法采样后再启用，未采样语言先只开 zh/en。
5. **默认值**：建议**默认关**、设置放免按区（与自动分段并列）。理由：命令词会拦截正文（用户真想输入「换行」二字时被吃掉），与自动分段"纯增益"不同，存在语义抢占，应 opt-in；UI 上列出词表让用户知情。
6. **竞品对照**：Wispr Flow command mode、Talon 均为公开资料印证方向（二手信息，未实测竞品）；SpeakType 的差异化在**纯本地、离线可用**（竞品命令多依赖云端/常驻 grammar 引擎）。

**结论：可进入开发。最小集（换行/另起一段/删除上一句/撤销）+ 整句精确匹配（去尾标点、按句号切分）+ finalize 挂点 + 默认关，估 0.5~1 轮含回归。**
