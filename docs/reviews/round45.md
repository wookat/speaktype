## 三、短句 30+ 轮连击（状态机全过，暴露 1 个 P3 设计问题）

RightCtrl 短按（~1.2s/轮、间隔 600ms）连续 32 轮【实测】：32/32 全部落字、顺序正确、无卡死、无串句、busy 状态机无残留（结束后再次口述正常）。超短语音（两词）的识别错误（Tap→Tab 等）属模型范畴。

**P3（新，设计论证候选）**：**hold 模式连续两句之间不补空格**——实测落字 "…works fine.Tap oneTap two…" 直接粘连；而免按模式有 handsFreeTyped 补空格逻辑【源码 dictation.ts:133】，hold 模式完全没有。用户对着同一文档连续按键口述是常见形态，粘连需要手动修。建议论证：hold 模式在「距上次落字 < N 秒且前台窗口未变」时沿用同款补空格判定（拉丁/数字开头才补），风险与免按一致、~10 行。
